1. БАЗОВАЯ ЛОГИКА GIT
================================================================================

Рабочая папка
      |
      | git add
      v
Staging Area
      |
      | git commit
      v
Локальная история Git
      |
      | git push
      v
GitHub

Обратное направление:

GitHub
   |
   | git pull
   v
Локальный Git


ГЛАВНАЯ ФОРМУЛА:
STATUS -> ADD -> COMMIT -> PUSH

То есть:

1. Проверил состояние
2. Подготовил изменения
3. Создал commit
4. Отправил на GitHub

# Проверить версию Git

git remote -v

# Посмотреть последние коммиты
git log --oneline -5


================================================================================
3. GIT STATUS — САМАЯ ВАЖНАЯ КОМАНДА
================================================================================

git status

Показывает:
- текущую ветку;
- изменённые файлы;
- подготовленные файлы;
- новые файлы;
- удалённые файлы;
- состояние связи с GitHub.

Пример:

On branch main
nothing to commit, working tree clean

Это означает:
Репозиторий чистый, незакоммиченных изменений нет.


================================================================================
4. СОЗДАНИЕ GIT-РЕПОЗИТОРИЯ
================================================================================

# Перейти в папку проекта
cd ~/путь/к/проекту

# Создать Git-репозиторий
git init

# Проверить
git status

ВАЖНО:
git init обычно выполняется один раз для проекта.


================================================================================
5. GIT ADD
================================================================================

# Добавить конкретный файл
git add my_dream.txt

# Добавить все изменения
git add .

Что делает git add:
Перемещает изменения в Staging Area.

ВАЖНО:
git add НЕ отправляет изменения на GitHub.

Проверка:

git add my_dream.txt
git status

После этого файл должен появиться в:

Changes to be committed:


================================================================================
6. GIT COMMIT
================================================================================

# Создать commit
git commit -m "Update my dream"

Что делает commit:
Создаёт сохранённую точку в истории Git.

Хороший commit:
git commit -m "Add homework 7"

Плохой commit:
git commit -m "aaa"

Правило:
Сообщение должно коротко объяснять, что изменилось.


================================================================================
7. GIT PUSH
================================================================================

# Отправить изменения на GitHub
git push

Первый push новой ветки:

git push -u origin my_second_git

После этого обычно достаточно:

git push

Логика:

git commit
     |
     v
локально сохранено
     |
     | git push
     v
GitHub


================================================================================
8. GIT PULL
================================================================================

# Получить изменения с GitHub
git pull origin main

Обычно перед началом работы:

git checkout main
git pull origin main

После этого можно создавать новую ветку.


================================================================================
9. ВЕТКИ — BRANCH
================================================================================

# Посмотреть локальные ветки
git branch

# Посмотреть все ветки
git branch -a

# Создать ветку
git branch my_first_git

# Перейти в существующую ветку
git checkout my_first_git

# Создать ветку и сразу перейти
git checkout -b my_first_git

Современный вариант:

git switch my_first_git

git switch -c my_first_git


ПРИМЕР:

git checkout main
git pull origin main
git checkout -b homework-7

Теперь работа идёт в:

homework-7


================================================================================
10. КАК ПОНЯТЬ, В КАКОЙ ТЫ ВЕТКЕ
================================================================================

git branch

Пример:

* main
  my_first_git
  my_second_git

Звёздочка (*) показывает текущую ветку.

Также:

git status

Пример:

On branch my_second_git

Значит сейчас ты в my_second_git.


================================================================================
11. GITHUB REMOTE
================================================================================

# Проверить подключение
git remote -v

Пример:

origin  https://github.com/USERNAME/project.git (fetch)
origin  https://github.com/USERNAME/project.git (push)

origin — стандартное имя GitHub-репозитория.


Добавить GitHub:

git remote add origin https://github.com/USERNAME/project.git

Проверить:

git remote -v

================================================================================
14. PULL REQUEST
================================================================================

Pull Request (PR) — предложение добавить изменения из одной ветки в другую.

Например:

my_second_git
      |
      | Pull Request
      v
main


ПОРЯДОК:

1. Создать ветку:
git checkout -b my_second_git

2. Изменить файлы.

3. Добавить:
git add .

4. Commit:
git commit -m "Update homework"

5. Push:
git push -u origin my_second_git

6. Открыть GitHub.

7. Выбрать Pull Request.

8. Base:
main

9. Compare:
my_second_git

10. Create pull request.

11. Проверить изменения.

12. Merge pull request.


================================================================================
15. ПОСЛЕ MERGE НА GITHUB
================================================================================

# Вернуться в main
git checkout main

# Получить изменения
git pull origin main

# Проверить
git status

# Посмотреть историю
git log --oneline -5


================================================================================
16. MERGE ЛОКАЛЬНО
================================================================================

Чтобы влить my_first_git в main:

# Перейти в main
git checkout main

# Обновить main
git pull origin main

# Влить ветку
git merge my_first_git

# Проверить
git status


ВАЖНО:
Команду merge выполняем в той ветке,
КУДА хотим добавить изменения.


================================================================================
17. GIT LOG
================================================================================

# Полная история
git log

# Короткая история
git log --oneline

# Последние 5 коммитов
git log --oneline -5

# Красивая история всех веток
git log --oneline --decorate --graph --all

# Посмотреть конкретный commit
git show 160acee

160acee — пример hash коммита.


================================================================================
18. GIT DIFF
================================================================================

# Посмотреть незакоммиченные изменения
git diff

# Посмотреть staged изменения
git diff --staged

Пример:

git diff
# показывает, что изменилось после последнего commit

git add my_dream.txt
git diff --staged
# показывает, что попадёт в следующий commit


================================================================================
19. ОТМЕНА ADD
================================================================================

Если случайно сделал:

git add my_dream.txt

Но передумал:

git restore --staged my_dream.txt

ВАЖНО:
Файл не удаляется.
Изменения остаются.
Просто файл убирается из staging.


================================================================================
20. ОТМЕНА НЕЗАКОММИЧЕННЫХ ИЗМЕНЕНИЙ
================================================================================

git restore my_dream.txt

Это возвращает файл к последнему commit.

ВНИМАНИЕ:
Незакоммиченные изменения будут потеряны.

Перед этой командой лучше проверить:

git diff

21. УДАЛЕНИЕ ФАЙЛА
================================================================================

# Удалить файл через Git
git rm my_dream.txt

После этого:

git status

Затем:

git commit -m "Delete my dream"

ПРИМЕР:

git rm "рука.jpg"

Если имя содержит пробелы или специальные символы,
лучше использовать кавычки.

22. УДАЛЕНИЕ ВЕТКИ
================================================================================

# Удалить локальную ветку
git branch -d my_first_git

# Принудительно удалить локальную ветку
git branch -D my_first_git

# Удалить ветку на GitHub
git push origin --delete my_first_git


================================================================================
23. CONFLICT — КОНФЛИКТ
================================================================================

Конфликт появляется, когда Git не может автоматически
объединить два разных изменения одного участка файла.

Проверить конфликт:

git status

После ручного исправления файла:

git add .
git commit -m "Resolve merge conflict"

Затем:

git push


================================================================================
24. ЧТО ДЕЛАТЬ, ЕСЛИ НЕ ПОНИМАЕШЬ, ЧТО ПРОИЗОШЛО
================================================================================

НЕ ПАНИКОВАТЬ.

Сначала:

git status

Потом:

git branch

Потом:

git log --oneline -5

Потом:

git remote -v

Если нужно увидеть изменения:

git diff


НЕ ИСПОЛЬЗОВАТЬ СРАЗУ:
git reset --hard
rm -rf
git clean -fd

Эти команды могут удалить изменения.

25. ТИПИЧНЫЕ ОШИБКИ
================================================================================

ОШИБКА:
git: 'comit' is not a git command.

ПРИЧИНА:
Опечатка.

ПРАВИЛЬНО:

git commit


ОШИБКА:
fatal: a branch named 'my_third_git' already exists

ПРИЧИНА:
Такая ветка уже существует.

Проверить:

git branch

Если нужно перейти:

git checkout my_third_git


ОШИБКА:
fatal: pathspec 'my_dream.txt' did not match any files

ПРИЧИНА:
Файл отсутствует в текущем состоянии рабочей ветки
или имя/путь указан неправильно.

Проверить:

ls -lah
git status
git ls-files


ОШИБКА:
Everything up-to-date

Это НЕ ошибка.

Это означает:
На GitHub уже находится та же версия,
что и локально отправляемая ветка.

26. WARNING: PERMISSION DENIED ~/.config/git
================================================================================

Если появляется:

warning: unable to access
'/Users/oleg/.config/git/ignore': Permission denied

или:

warning: unable to access
'/Users/oleg/.config/git/attributes': Permission denied

Git может продолжать работать.

Сначала проверить:

git status

Если команда работает и показывает правильную ветку,
не нужно удалять проект или папку .git.


Дополнительная диагностика:

git config --list --show-origin
git config --global --list

28. GIT STATUS — КОРОТКИЕ ОБОЗНАЧЕНИЯ
================================================================================

git status --short

Пример:

M  my_dream.txt
 M .DS_Store
?? course_2/

Что означает:

M  = файл изменён и уже staged
 M = файл изменён, но ещё НЕ staged
?? = новый файл, Git его ещё не отслеживает

39. ГЛАВНОЕ ПРАВИЛО
================================================================================

ЕСЛИ НЕ ЗНАЕШЬ, ЧТО ДЕЛАТЬ:

1. НЕ выполняй опасные команды.
2. Выполни:

git status

3. Посмотри ветку:

git branch

4. Посмотри историю:

git log --oneline -5

5. Посмотри изменения:

git diff

После этого обычно становится понятно,
что происходит.
